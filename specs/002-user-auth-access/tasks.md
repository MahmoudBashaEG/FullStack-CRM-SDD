## Supported Authentication Scope

The application supports one active browser tab per signed-in session. Multiple simultaneously active tabs sharing the same authentication session are outside the supported scope of this feature. Cross-tab synchronization, Web Locks, BroadcastChannel and cross-tab locking infrastructure are out of scope. PG-001 is resolved by the approved single-tab design; there is no remaining browser-fallback gate.

Within one Angular instance, AuthService owns one shared in-flight refresh through response parsing and identity restoration. Concurrent requests join it, the new memory JWT is published before waiters retry, and each eligible request replays at most once. Late old-token401 responses reuse an already-renewed JWT without redundant rotation. Any refresh failure clears JWT/current identity and fails all waiters; safe503/network unavailable diagnostics are retained without authenticated state or automatic loops. Signout/new signin invalidates stale completion and queued replay. Backend rotation remains atomic, with strict consumed-token replay rejection and no grace window. Separate browser cookie jars remain independent sessions.
