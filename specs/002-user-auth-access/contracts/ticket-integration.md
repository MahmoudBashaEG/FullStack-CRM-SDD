# Ticket Identity and Reference Transition Contract

This records Feature002 changes to Feature001 integration; it does not rewrite Feature001 historical spec/planning/evidence or change its ticket lifecycle REST payloads.

- Keep shared SupportQueue policy name; replace external crm_support_queue claim test with current local Agent/Admin authorization after server account/session validation. Visitor/invalid/revoked identity401; valid Customer403. Queue operations remain independent of assignment.
- ICurrentActor requires any trusted authenticated CRM account snapshot, rather than the old queue-specific gate; ticket endpoint policies independently require SupportQueue. It returns the trusted local snapshot through existing Actor value: issuer namespace urn:crm:local:user, canonical UserId as subject, current display name. No name claim is needed in JWT. Existing saved external actor snapshots remain exactly as stored; issuer-key configuration changes must not redefine local actor namespace.
- Ticket reference endpoints retain DTO shape/id fields. New active Agents are choices with new references; Admin/Customer never choices. Current detail still shows legacy/inactive references with effective isEligible=false. Clearing/retaining inactive assignment and unrelated/status mutations retain existing Feature001 semantics.
- Migration adds nullable unique AgentReference.LocalUserId; all existing references remain null and become ineligible. No relinking, account creation by identity matching, ticket FK replacement, deletion or history rewriting.
- Category provisioning CLI invocation/input/counts stay; nonempty agents array now rejected with existing validation exit2. Omitted/empty agents array remains valid category setup. It may not update linked Agent identities/eligibility. Production assignment identities are created only by local Agent creation; test setup must use that real path.
- Reference eligibility reads require linked active Agent as well as IsEligible; selected-reference transaction locks continue to protect new selections. Rename/disable update the linked reference under the account transaction; no new assignment can commit based on stale eligibility after disablement has committed.
- Existing backend auth fixtures, frontend injected-token adapter, external HTTPS test issuer and provisioning-based eligible Agent setup must be replaced by real local account/signin flows. Ephemeral certificates belong only to private test setup. Keep categories401 readiness, relative /api, proxy/TLS checks, owned SQL cleanup and all substantive ticket assertions.
- After implementation update live developer setup links; historical OIDC validation documents remain historical. No parallel legacy provider or token adapter remains active in production or Testing.

Regression matrix: Agent/Admin each exercise create/view/list/edit/assign/lifecycle/history; Customer/visitor denied; unchanged stale-version/closed-ticket/atomic history rules; disabled and legacy assignments readable/retainable/clearable; legacy actors byte-preserved; new actors use trusted stable UserId; CLI cannot re-enable legacy eligibility.
